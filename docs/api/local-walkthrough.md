# 本机 API 联调

启动应用后，在首页选择「检查服务连接」，也可以直接访问 `/health`。页面调用同源 `GET /api/health`，仅在服务器返回 `{"status":"UP","application":"group-photo-consensus"}` 时显示连接正常。故障与重试操作见[连接恢复验收](#验证连接失败与恢复)。

按 [README](../../README.md) 初始化环境、检查依赖并运行 `./scripts/dev.sh`。已有 `.env` 需要分别配置两个随机令牌，对应 `organizer` 和 `participant`。以下命令读取本机配置，上传一张程序生成的像素图，并核对活动权限、缩略图和授权修订。

在另一个终端回到仓库根目录，执行：

```sh
SMOKE_STATE=$(mktemp "${TMPDIR:-/tmp}/frame-and-say-smoke.XXXXXX")
node --env-file=.env scripts/smoke-compose.mjs create "$SMOKE_STATE"
```

此脚本通过前端端口请求同源 `/api`，也直接检查后端 readiness。它可用于默认端口的本机 Vite/H2 环境，或 Compose 提供的 Nginx/MySQL 环境。脚本检查双身份的成员查询、非成员 `403`、跨活动照片 `404`、代签拒绝、群内与公开用途隔离，以及名单变更后的旧修订 `409`、刷新与本人再次确认。具体字段见 [OpenAPI 契约](openapi.yaml)。

使用 MySQL 和持久化图片目录时，保留上面的临时状态文件。先重启 MySQL 和后端，再验证先前创建的活动、成员关系、照片元数据及缩略图仍可读取。

```sh
node --env-file=.env scripts/smoke-compose.mjs verify "$SMOKE_STATE"
rm "$SMOKE_STATE"
```

本机 H2 重启后会清空。用 H2 联调只运行 `create`，完成后可直接删除临时状态文件。联调使用合成数据，建议为联调指定 `APP_PHOTO_DIR` 专用目录。

前端读取缩略图时，用 `fetch` 带上活动成员令牌，再用返回的 Blob 创建对象 URL，离开页面时回收。联调接口保留未评分的 `null`，区别于中性偏好 `0`。改动授权时先读取当前 `subjectRevision`，收到 `409` 后刷新界面并让用户重新确认。联调令牌只用于本机。正式登录和推荐调用仍由对应成员开发。

从首页选择「打开联调相册」，进入 `/album`。先连接当前活动成员的本机令牌，再选择脚本创建的活动。令牌保存在当前标签页的会话存储，选择「断开联调身份」可清除。照片详情地址包含活动、照片和当前所选版本的标识。用没有加入活动的令牌打开该地址时，页面提示无法访问。

## 验证连接失败与恢复

1. 从干净检出开始，记录 Java、Node.js 和 pnpm 版本。按照 [README](../../README.md#开发与测试) 或 [Windows 构建步骤](../windows-local-development.md#构建与测试) 安装依赖、运行前后端测试并打包，确认命令退出码为 0。
2. 在仓库根目录的两个终端分别运行 `pnpm --dir frontend dev` 和 `node scripts/dev.mjs --backend-only`。Windows PowerShell 使用 `pnpm.cmd`。初始化本机联调令牌后，在「我的活动」连接发起人身份。需要保留重启前的数据时，启动 `docker compose up -d --wait mysql`，并在启动和恢复后端时都使用 `node scripts/dev.mjs --local --backend-only`。在断连前建一个合成活动、邀请成员并上传一张合成照片。
3. 打开「服务连接」，确认显示「连接正常」。在后端终端按 `Ctrl+C` 后，在同一浏览器页面点「重新检查」，或重新打开 `/health`。应能看到失败提示和可点击的「重新检查」，之前的成功状态和检查时间消失。保持后端停止时访问「我的活动」，列表应显示读取失败，并提供「重试活动列表」。
4. 在后端终端重新执行启动命令，在浏览器点「重新检查」，确认恢复为「连接正常」。打开「我的活动」，刷新或重试列表，点击合成活动并确认相册能读取缩略图。默认内存 H2 重启会清空演示数据，需在恢复后重新创建活动和上传照片；使用前一步的 MySQL 环境则核对重启前的活动和照片。
5. 核对持久化环境时，用原活动成员打开照片，确认之前保存的评分和对应分享用途的决定仍可读取。没有加入活动的身份无法查看该相册。

## 创建和找回我的活动

1. 在主导航打开「我的活动」（`/events`），用本机 `.env` 中的 `APP_BOOTSTRAP_ORGANIZER_TOKEN` 连接。在全新的 H2 demo 环境中，「已加入的活动」显示为空。
2. 以「秋游」为名、目标 3 张创建活动。页面通过同源 `POST /api/events` 提交名称和可选目标，后端根据 Bearer 身份设置发起人。成功后页面重新读取 `GET /api/events`，点击「秋游」可进入它的相册。
3. 名称支持 1–80 个字符且须含非空白字符。选片目标可留空或填写 1–100 的整数。如果创建时断网、超时或收到 5xx，页面保留输入并暂停提交。点击「核对活动列表」重新读取当前身份的活动。找到本次活动时点「已找到该活动」结束；确认列表中没有时点「未找到，返回表单」，以相同输入重试时沿用原请求标识，即使首次事务稍后才提交，也只会创建一个活动。在同一标签页刷新后，页面会恢复当前身份的名称、目标和请求标识，并重新读取列表供核对。切换到其他身份时，该表单只显示对应身份的待确认活动。创建成功或选择「已找到该活动」后，页面清除本次记录。列表读取失败时可以再次核对。若已提示创建成功而列表加载失败，点击「重试活动列表」即可。
4. 断开当前身份，使用 `APP_BOOTSTRAP_PARTICIPANT_TOKEN` 连接。该成员的列表中应看不到刚创建且尚未邀请其加入的「秋游」。用此身份打开之前的相册地址也不能读取活动照片。

## 上传活动照片

1. 用活动成员的本机令牌进入相册，并选择一个可访问的活动。
2. 在照片列表上方选择一张合成 JPEG 或 PNG，再点「上传照片」。成功后相册会刷新列表，成员可直接查看新照片的缩略图。
3. 再把内容为文本、文件名为 `pretender.png` 的文件提交到同一活动。服务端会拒绝并返回 `415`，页面提示图片不可解码，刷新列表后仍只有合法文件新增的那一张。

单张文件最多 8 MiB，服务端还会检查实际编码和图像尺寸。上传遇到网关 `502` / `504` 或连接中断时，先点击「刷新照片列表」。页面只读取列表，核对前暂停提交。刷新成功后，若已找到照片就结束核对；若未找到，可重新选择文件后手动提交。刷新失败时可继续刷新。初次上传创建版本 1，出镜名单尚未确认。

## 评分和授权过期后的刷新约定

评分遇到 409 时，点击「刷新相册」并重新打开当前照片版本，再选择评分。临时请求失败后可继续重试同一个评分。

1. 收到授权请求的 409 后，清除尚未保存的同意/拒绝选择，提示照片或出镜信息已更新。
2. 点击「刷新照片和名单状态」。若当前版本仍有效，页面重新读取该用途的最新修订和 `canDecide`。若照片已换版，页面会在同一次操作中刷新列表，请再打开新版本。
3. 普通出镜者不调用发起人专用的出镜名单 GET 接口。若 `canDecide=false`，显示当前无法确认，等待发起人核实名单。
4. 若可决定，展示当前照片和用途，由本人再次作出选择后提交；不自动重放先前的同意。刷新期间遇到再次更新时，继续按 409 处理。

`MyConsent` 的五个字段和原有 204/400/403/404/409 响应状态保持一致，与 #53 的调用结构兼容。完整边界样例及本轮结果见[授权边界验证](authorization-boundaries.md)。

## 保存和比较照片版本

在相册中打开一张照片，用「照片版本」切换当前及历史缩略图。原上传者或活动发起人可在当前版本下选择修改后的 JPEG 或 PNG，再点「保存为新版本」。相册仍显示同一张照片，详情会切换到新版本；历史版本及其图片保留。对于没有上传者记录的旧照片，发起人可以提交新版本。

切换到版本 1 后复制详情地址并重新打开，应仍显示版本 1。保存版本 2 后，旧格式的 `?event=<活动 ID>&photo=<版本 1 ID>` 也应打开版本 1。

新的版本必须重新确认出镜名单、按用途取得授权。若当前版本已更新，或保存时收到 502、504 或连接中断，页面会要求先刷新版本列表。核对当前版本后，如需再次提交，重新选择文件。[API 契约](openapi.yaml)记录了 `baseVersionId` 和相关响应。

## 复核移动端相册

1. 运行本页的 `create` 联调脚本，在同一活动再上传一张合成图片。用发起人身份确认两张照片的名单，确保只有一张列有 `participant`。
2. 在浏览器设定 375×667 的视口，以 `participant` 身份进入相册。确认列表的两张图片可见，打开有本人出镜的照片后，焦点落在照片标题。
3. 保存 0 分，再同意活动群内分享。刷新详情，核对「当前评分 0」和「当前决定 已同意」。切换到公开发布，核对该用途仍待确认。
4. 详情、相册列表和表单均应在视口宽度内。打开控制台确认 `document.documentElement.scrollWidth === window.innerWidth`。返回列表后，焦点落在活动标题。

## 复核发起人的分享进度

在同一活动准备三张照片，为同一用途分别留下已同意、待确认、已拒绝的出镜者决定。用发起人令牌在相册列表切换用途，核对符合分享条件和需处理两种状态。普通成员的相册列表只显示照片，进入详情后可查看本人的用途决定。

读取列表与汇总之间新增照片或替换版本时，汇总会提示数据不同步。点击「刷新相册和分享进度」后，页面重新加载两份数据并保留当前用途。

## 演示身份的启用范围

`app.bootstrap.enabled` 在基础配置中默认关闭，仅 demo、local、test 配置启用。关闭时，配置了两个演示令牌也不能认证；在其他环境或混合生产环境中强制启用会阻止启动。使用额外的本机 profile 时，需要显式选择允许的环境，不能将演示身份开关带入正式部署。

正式登录与邀请的迁移步骤见[身份与邀请方案（待评审）](identity-invitations.md)。当前 `addEventMember` 只添加已配置的合成成员，不代表已经实现邀请。

## 导出经过复核的照片

发起人核对所需照片后，向 `POST /api/events/{eventId}/confirmed-selections` 提交用途和有序条目。每条包含 `photoId`、`photoVersionId`、`subjectRevision`。保存成功后，用同一身份调用 `GET /api/events/{eventId}/confirmed-selections/{selectionId}/export` 下载 ZIP。实际文件按版本 ID 命名，每个条目都是原图。导出直接读取服务端清单，已有授权只适用于对应的用途。

在专用合成活动环境中可运行以下冒烟检查。它创建两张已许可照片和一张清单外的照片，解压比较首次 ZIP 的原图，再撤回第二张照片的群内许可并确认重新下载返回 `409`。

```sh
EXPORT_STATE=$(mktemp "${TMPDIR:-/tmp}/frame-and-say-export.XXXXXX")
node --env-file=.env scripts/smoke-reviewed-export.mjs create "$EXPORT_STATE"
```

示例 ZIP 位于 `"$EXPORT_STATE.zip"`。使用持久化数据库时，可在重启后执行 `node --env-file=.env scripts/smoke-reviewed-export.mjs verify "$EXPORT_STATE"`，验证同一清单仍拒绝交付。完成后删除状态文件和样例 ZIP。

## 申请删除活动照片

原上传者用本人令牌向 `POST /api/events/{eventId}/photos/{photoId}/deletion-request` 提交申请。发起人通过 `GET /api/events/{eventId}/photo-deletion-requests` 查找申请，再以 `PUT /api/events/{eventId}/photos/{photoId}/deletion-request/approval` 批准。申请者或发起人可读取该照片的 `GET .../deletion-request`，核对申请人、处理人、时间和状态。

处理前，缩略图和已有合法导出仍可读取。批准后，相册和发起人的分享进度都移除整张照片，分享进度仍显示其余照片的当前版本。各版本旧链接返回 `404`，包含该照片的确认清单返回 `409`，发起人可重新确认仍有效的照片。处理记录和私有文件保留，实际清理与保留期限另行确定。未记载上传者的旧照片不能通过此流程申请。

用合成数据复验本流程：

```sh
DELETE_STATE=$(mktemp "${TMPDIR:-/tmp}/frame-and-say-deletion.XXXXXX")
node --env-file=.env scripts/smoke-photo-deletion.mjs create "$DELETE_STATE"
```

如果使用持久化数据库，可在重启后运行 `node --env-file=.env scripts/smoke-photo-deletion.mjs verify "$DELETE_STATE"`，核对已批准记录、剩余照片的分享进度、旧链接和确认清单。结束后删除临时状态文件。

## 图片存储与输入边界回归

在仓库根目录执行：

```sh
./scripts/maven.sh -B -Dtest=PhotoImageProcessorTest,LocalPhotoStorageTest,PhotoWorkflowIntegrationTest test
```

Windows 可在 `backend` 目录用 `./mvnw.cmd -B '-Dtest=PhotoImageProcessorTest,LocalPhotoStorageTest,PhotoWorkflowIntegrationTest' test`。两种方式都需要 Java 21。
这组测试用内存合成的 JPEG/PNG 和 JUnit 自动清理的临时目录，验证内容解码、文件/像素边界、文件名与存储键隔离、受保护缩略图及拒绝上传无残留。
仅验证 H2 和本地文件适配器；Docker/MinIO、代理限额及持久化需独立联调。当前实测环境和结果见 [私有图片存储与输入校验记录](../verification-log.md#2026-11-24-私有图片存储与输入校验)。

## 调整活动选片目标

用发起人 A 的本机身份打开活动相册，选择已有活动。在「调整目标」中填写 1–100 的整数，点击「保存目标」。活动原先没有配置目标时也可在此首次设置。这个范围与活动创建及推荐接口一致，可在上传完整个相册前设定目标。

验收可使用五张合成照片和初始目标 3 张。A 改为 4 张后重新打开相册，当前目标应为 4 张。让已加入的普通成员 B 打开同一活动，页面应只显示当前目标。用 B 的身份向 `PUT /api/events/{eventId}/selection-target` 提交 `{"desiredPhotoCount":2}` 会返回 403，A 与 B 重新读取仍为 4 张。A 输入 0 或 101 时，页面提示有效范围，原值保留。
