# 用户角色与初步用例

这份候选清单用于 [#7 需求评审](https://github.com/Jdeciderz23/frame-and-say/issues/7)，本阶段使用公开证据，后续结合实际取得的匿名访谈纪要核对。用例 ID 保持稳定，对应故事和验收场景已列入追溯矩阵。当前已实现接口见 [OpenAPI](api/openapi.yaml)。

## 角色草案

| 角色 | 权限边界 |
|---|---|
| 活动发起人 | 创建和配置自己组织的活动，邀请成员，发起选片和导出；不能替别人授予照片发布许可 |
| 活动参与者 | 访问自己加入的活动、上传和评价照片，管理本人的发布授权；可提出出镜名单纠错需求，具体入口待评审 |
| 系统管理员 | 管理账户状态与系统异常；不因管理员身份获得个人照片查看权，不得替参与者签署发布授权 |

同一用户在不同活动中的身份独立。发起人也可以是出镜人员，其个人授权仍需单独记录。

## 业务规则草案

- 偏好只表达喜欢程度，拒绝发布是硬约束；“喜欢”不能自动视为同意公开。
- 发布授权至少绑定本人、照片版本、发布用途，默认未确认。
- 修改图片或修正出镜人员后，重新检查该版本、用途和授权主体集合；不得悄悄继承旧许可。
- 推荐前排除名单未确认，或在当前版本、用途及名单修订下存在拒绝或待确认授权的照片；导出前再次校验。可选数量不足时说明原因。
- 未评分的默认值、可撤销的时限、拒绝原因对谁展示，均属待确认问题。

前三个建议细化场景：UC-12授权、UC-15选片、UC-20重新确认；第一周收集示例，第二周先评审流程和异常分支。活动图和状态图应以确认后的流程为依据。

各用例的测试输入、预期结果和待评审权限见[SRS 草稿](11-srs-draft.md)。[追溯矩阵](13-traceability.md)保留稳定编号。
