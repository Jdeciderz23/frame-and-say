# 照有商量 · 项目范围

旅行或社团活动结束后，发起人需要从多位成员拍摄的照片中选出一组可以分享的合照。Frame & Say 把三个决定放在同一场活动里：哪些照片大家喜欢、出镜者同意哪些分享用途，以及最终交付哪个版本。设计规模为单场 5–10 人、最多 100 张照片。

## 交付范围

| 里程碑 | 用户能完成什么 | 如何验收 |
|---|---|---|
| [活动相册](https://github.com/Jdeciderz23/frame-and-say/milestone/1) | 创建和加入活动，上传并浏览照片 | 用两个活动验证访问隔离；合法图片有受保护的缩略图，非法文件被拒 |
| [偏好与分享确认](https://github.com/Jdeciderz23/frame-and-say/milestone/2) | 评价照片，按用途决定本人是否同意分享 | 未评分与 0 分可区分；名单修订或图片版本变化后，旧许可失效 |
| [公平选片与交付](https://github.com/Jdeciderz23/frame-and-say/milestone/3) | 获取可解释的选片建议，确认清单并导出 | 合成分歧样例可复算，候选不足时报告缺口，交付前复核最新授权 |

活动成员资格与照片版本是授权判断的输入，推荐和导出再消费授权结论。因此按上述顺序交付，每个阶段都能独立走查。当前可运行的功能见[项目首页](../README.md)，任务进度见[需求与交付计划](https://github.com/Jdeciderz23/frame-and-say/issues/19)。

## 产品和工程约束

出镜名单由发起人核实，出镜者分别确认群内分享和公开发布。上传、评分和浏览权限均以服务端识别的活动成员为准。文件交付后，系统能控制后续下载，已经下载的副本由接收者管理。

Vue 前端与 Spring Boot 后端独立构建。算法与业务模块共用 Java，H2 用于本地演示，持久化联调使用 MySQL。实现状态、API 契约与存储边界见[技术架构](03-architecture.md)。
