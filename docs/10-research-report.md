# 照有商量需求调研报告

项目名称为「照有商量 · Frame & Say」。本报告通过公开资料调研、同类产品功能梳理和业务流程分析，了解多人活动后的照片收集、共同选片与分享确认需求，为初步需求和后续用例分析提供依据。

## 一 调研背景与目的

### 1.1 项目背景

多人旅行、聚餐和集体活动会产生共同整理照片的需求。照片可能由不同成员拍摄，整理者需要将其收集起来，再组织大家挑选用于留念或分享的内容。在这一过程中，拍摄者关注照片质量，参与者关注自己的表情与喜好，出镜者还需要考虑照片将被分享给谁。

围绕同一张照片，不同成员可能有不同判断。组织者需要汇总意见、处理分歧并确定最终清单，也需要在分享前了解出镜者的决定。照片发生裁剪或调色后，最终分享的内容与此前讨论的内容还可能存在差异。

「照有商量」拟围绕一次活动建立共同选片空间，将照片、个人偏好、分享用途和确认状态集中呈现，帮助成员完成从收集照片到确认分享清单的过程。

### 1.2 调研目的

本次调研重点分析以下问题。

1. 照片怎样收集和挑选，各类参与者分别承担什么工作。
2. 成员偏好、分享用途和确认状态怎样影响最终选择。
3. 现有照片分享和选片工具提供了哪些可借鉴的操作方式。
4. 项目需要支持哪些功能，哪些业务规则仍需进一步讨论。

## 二 调研对象与方法

这些视角可以重合。例如，活动组织者出现在某张合照中时，也需要表达本人的分享意愿。

## 四 问题分析

### 4.1 公开案例反映的分享分歧

中国大学生在线于 2026 年 9 月 24 日发布的《同学的照片和聊天记录，可以随手发到网上吗？》叙述了一个宿舍照片分享案例。文中，一名学生睡觉时的照片被室友配文发到朋友圈，当事人发现后要求删除，双方因此产生分歧。[查看案例原文](https://dxs.moe.gov.cn/zx/a/hd_qwxywlwmy_wlsypy_wlsytszn/260924/2056526.shtml)

对本项目而言，该案例值得关注的问题是，发布者与出镜者可能对同一张照片的使用有不同理解。照片由谁持有、谁作出分享决定，以及分享前怎样沟通，会影响双方对最终结果的接受程度。

### 4.2 同类产品中的照片交流与选片

Google 相册的官方帮助说明介绍了共享相册、添加照片、评论和回应等操作，可以为共同浏览与围绕照片交流提供参考。[Google 相册官方说明](https://support.google.com/photos/answer/6131416?hl=zh-Hans)

Pixieset 的官方帮助说明介绍了收藏清单、照片备注，以及下载照片或导出收藏清单等操作，可以为整理个人选择和交付结果提供参考。[Pixieset 官方说明](https://help.pixieset.com/hc/en-us/articles/115003797011-Pixieset-and-Proofing)

两类功能为收集照片、表达选择和交付结果提供了参考。本项目还需分析，多人选择不一致时怎样协调，出镜者的分享决定怎样与最终清单关联。

### 4.3 照片和意见分散会增加核对工作

共同选片包含收集照片、初步挑选、征求意见和调整结果等环节。若照片与反馈分散在不同消息中，组织者需要反复辨认每条意见针对哪张照片，并核对是否采用了最新决定。

这里的沟通成本集中在找图、确认反馈对象和调整后的再次询问。照片数量、沟通轮次和实际耗时会随活动规模变化，本轮重点分析这些重复操作产生的原因。

### 4.4 喜好和分享决定包含不同信息

成员评价照片时，关注构图、表情或个人偏好。成员决定是否分享时，还需要考虑用途和展示范围。同一个人的两类判断可能不同，群内分享与公开发布也可能涉及不同决定。

未回复、明确同意和明确拒绝分别反映不同状态。组织者若无法清楚区分，就难以判断接下来应继续沟通还是调整清单。决定发生修改时，还需要核对后续使用是否采用了最新状态。

### 4.5 整体高分可能掩盖个人意见

共同选片涉及多个人的偏好。若只按照片总分排序，成员之间的感受分布可能被忽略，例如某人的意见在多个结果中都没有得到体现。因此，选择一组照片时需要讨论各人的偏好怎样共同影响结果。

未出镜成员能否参与评价、未评分怎样处理，以及怎样理解公平性，会直接影响推荐规则。成员也需要理解推荐为什么采用某些照片，组织者则需要知道可选数量不足的原因。

### 4.6 照片修改和名单纠正会影响原先确认

裁剪、调色等操作可能改变照片内容，原先看过的图片与最终准备交付的图片可能存在差异。人工标记出镜人员时，也可能出现漏标或错标，使需要确认的人发生变化。

这类变化涉及确认针对哪一版照片，以及由哪些人作出决定。参与者发现漏标或错标时可以提出纠错，由活动发起人核实、确认和更新正式出镜名单。名单发生有效变更后会形成新的修订，原修订下的分享决定不沿用，需要按新名单重新收集确认。照片形成新版本时，也需要针对新版本重新确认。

### 4.7 使用环境和保存安排影响完整体验

共同浏览、评价和确认需要适应手机操作。网络较差时，成员需要知道上传或保存是否成功，并能方便地继续处理。

导出原图、压缩包或文件清单会带来不同的整理方式。照片对谁可见、活动结束后保留多久、谁可以申请删除，以及已导出后修改决定适用于什么范围，也会影响使用过程。

## 五 调研发现

### 5.1 意见需要落到具体照片上

根据第 4.2、4.3 节的产品资料和业务分析，可以归纳出集中展示与逐张记录意见的价值。成员找到同一张照片，并围绕它查看最新反馈，有助于减少找图和重复核对。

### 5.2 分享确认需要明确用途和状态

公开案例与第 4.4 节的分析表明，分享沟通需要明确照片准备怎样使用，以及出镜者已经作出什么决定。喜好、同意、拒绝和待确认需要具有清楚的含义。

### 5.3 组合选择需要保留个人意见

第 4.5 节的分析提出，照片总分与个人体验需要一起考虑。推荐应向成员提供讨论依据，并给出容易理解的理由。可选数量不足时，也需要说明当前缺少哪些条件。

### 5.4 确认需要与照片版本及出镜人员关联

第 4.6 节的分析提出，照片变化和名单纠正都可能改变原先确认的基础。推荐前应核对当前照片版本、用途、已确认的出镜名单及其修订，只有名单中的所有人均明确同意时才纳入候选；最终导出前还应重新核验最新状态。

### 5.5 完成选片还涉及使用与交付

根据第 4.7 节的分析，手机操作、失败反馈、导出形式、照片保存与删除安排都影响成员能否顺利完成选片。这些事项应和核心功能一起纳入需求讨论。

以上为公开资料和业务分析形成的认识，相关规则继续由团队评审确认。

### 6.2 使用体验与隐私需求

- 手机页面上的浏览、评价、分享确认和查看状态操作应容易找到。
- 照片与意见按活动管理，成员提交本人的评价和分享决定。
- 上传或保存失败时，应提示当前结果并提供重试入口。
- 账户维护角色的操作边界、个人拒绝信息的可见范围需要明确。
- 导出形式、照片保存期限和删除入口应有清楚说明。

这些需求在评审后进一步转为可检查的标准。

## 七 系统拟支持的业务流程

### 7.1 从创建活动到交付照片

依据前述初步需求，系统拟按以下过程支持成员完成共同选片。

| 步骤 | 用户操作与系统支持 | 相关用户故事 |
|---|---|---|
| 创建活动并邀请成员 | 发起人建立本次选片空间，邀请参加者加入。 | US-01、US-02 |
| 上传照片并核对出镜人员 | 成员集中上传和浏览照片，发现漏标或错标时提出纠错；活动发起人核实、确认和更新出镜名单。 | US-03、US-04 |
| 分别表达偏好和分享决定 | 成员提交喜好，出镜者按用途作出分享决定。 | US-05、US-06 |
| 查看进度并形成推荐 | 发起人查看仍缺的确认，系统仅在出镜名单已确认、所有出镜者均同意当前版本用于本次用途的照片中提供组合建议和理由。 | US-07、US-08 |
| 讨论与调整结果 | 成员查看推荐并讨论调整。照片形成新版本或发起人有效更新名单时，重新收集确认，再判断是否可参与推荐。 | US-04、US-06、US-08、US-09 |
| 确认清单并导出 | 发起人确定最终清单，系统核对最新分享条件，交付对应版本的文件。 | US-10 |

### 7.2 特殊业务情形

推荐前必须核对当前照片版本、分享用途和出镜名单修订。只有名单已确认，且名单中的每个人都对该版本、用途和名单修订明确同意，照片才可进入推荐；最终导出前仍需重新核验最新状态。这与现有[技术架构中的照片授权规则](03-architecture.md#照片授权)一致。

| 情形 | 需要支持的处理方向 |
|---|---|
| 出镜名单未确认 | 推荐阶段即排除该照片，待活动发起人确认名单后，按当前版本、用途和名单修订重新判断；条件不满足时不允许导出。 |
| 有人拒绝 | 在相应用途的推荐候选中排除该照片，提示汇总原因，供组织者重新选择；导出前再次核验，仍被拒绝时不允许交付。 |
| 有人未确认 | 显示待确认状态并在推荐阶段排除该照片；导出前再次核验，仍有人未确认时不允许交付。 |
| 出镜名单纠正 | 参与者提出纠错，由活动发起人核实并更新名单。每次有效变更更新名单修订，原修订下的分享决定不沿用，需重新收集确认后再判断能否推荐。 |
| 有人未评分 | 保留未评分状态，处理规则在评审中确定。 |
| 图片被修改 | 展示新版本，原版本的分享决定不沿用；按新版本、用途和已确认的名单重新收集决定，满足条件后才可参与推荐。 |
| 可用照片不足 | 显示实际可选数量及汇总原因，允许调整目标数量。 |

## 八 调研结论与待确认事项

### 8.1 调研结论

公开案例体现了照片分享前沟通的重要性，产品资料提供了集中看图、记录个人选择与汇总结果的功能参考。结合业务流程分析，本项目将初步需求归纳为三个相互衔接的方面，即活动照片管理、个人意见表达、最终清单与分享确认。

建议先让成员能够在同一活动中收集照片、表达偏好与分享决定，再提供组合建议和结果说明，最后完成清单确认与导出。

### 8.2 项目范围

依据现有[项目启动说明](00-project-brief.md)，项目初步按每场活动五至十人、最多一百张照片设计，出镜人员采用人工标记。首版聚焦共同选片与分享确认，具体规模和功能优先级在团队评审后确定。

### 8.3 待确认事项

出镜名单由活动发起人确认和更新，参与者可以提出纠错。名单未确认或有人待确认、拒绝时，按第 7.2 节在推荐阶段排除，导出前再核验；这些规则已明确。以下继续讨论提醒、决定修改时限和操作呈现等细节。

| 问题 | 需要作出的决定 |
|---|---|
| 偏好与未评分 | 采用怎样的评价档位，未评分是否影响推荐。 |
| 分享提醒与决定修改 | 群内分享与公开发布分别确认；待确认时怎样提醒，修改或撤回决定的时限如何设置。 |
| 名单纠错沟通 | 参与者通过什么入口提出纠错，发起人怎样处理异议并告知结果。 |
| 图片修改 | 原版与新版怎样对比呈现，再次确认的提醒如何展示。 |
| 公平性与解释 | 怎样考虑个人偏好，页面解释展示哪些信息。 |
| 使用与导出 | 手机操作怎样安排，优先提供哪种导出形式。 |
| 保存与删除 | 照片保留多久，删除权限和已导出文件怎样处理。 |

后续可以通过原型体验观察成员是否能够找到照片、理解确认用途并完成选择，依据反馈调整规则和需求优先级。
