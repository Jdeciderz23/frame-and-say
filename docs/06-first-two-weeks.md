## 第二周：五个可运行、可测试的模块起点

| ID | 负责人/开发任务 | 范围与完成标准 | 任务依赖 |
|---|---|---|---|
| W2-01 | 成员1：活动创建全栈 | 沿用现有创建和列表接口，实现表单、列表及错误处理。用合成身份联调；有 MySQL 环境时验证重启后数据仍在 | W1-01/03/07 |
| W2-02 | 成员2：照片浏览评价起点 | 用合成图片接入手机宽度浏览、本人偏好和授权。授权过期时重新读取名单，网络失败可重试 | W1-02/07；与3/5按契约对接 |
| W2-03 | 成员3：成员权限与授权模型 | 复核成员查询、活动隔离与授权修订。补齐联调发现的边界测试，提出正式登录与邀请方案 | W1-03/07 |
| W2-04 | 成员4：公平选择原型 | 纯Java算法在完整模拟评分上运行；先执行硬约束过滤；输出确定结果、效用和不足原因；与普通总分排序比一个构造案例；算法/边界测试通过 | W1-04/07；策略接口可先模拟 |
| W2-05 | 成员5：单张上传与缩略图 | 验证 JPEG/PNG 上传限额、受保护缩略图、文件持久化及异常情况。MinIO 适配器依独立验证结果推进 | W1-05/07；真实访问联调依赖W2-03 |

第二周的并行方式：五人先按评审后的契约和测试夹具独立实现。成员 3 负责权限和授权边界复核，成员 1、2、5 使用现有契约并行接入；成员4始终不能把前端传来的“已授权”当可信输入。准备一个小型接口样例包，验证活动ID、照片版本ID、成员ID、用途枚举在模块间一致。

## 第二周末共同检查

- 每人演示自己的代码和测试，说明哪些是真实接口、哪些仍为模拟；不以静态页面替代后端实现声明。
- 共同跑基础构建及测试，至少完成一条健康联通请求和一组跨模块契约样例；业务未接通的接口列入阻塞，不假称完整系统。
- 复核非成员、未确认授权和新图片版本不会被错误放行。未完成权限的业务接口不对公网开放。
- 汇总实际工时、PR/Issue、评审与AI使用记录；检查每人的编码负担并调整本轮任务。
- 保留真实访谈结论、需求变更和待确认清单；本文件不安排前两周之外的工作。

项目周编号与 GitHub Issue 的对应关系见[任务索引](08-issue-backlog.md)。提交与评审使用仓库的[协作指南](../CONTRIBUTING.md)。
